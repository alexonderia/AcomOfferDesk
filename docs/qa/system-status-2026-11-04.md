# Проверка панели состояния — 04.11.2026

## Что проверить

1. СА открывает «Состояние системы» в меню; на мобильном — через «Прочее». Ссылка работает, остальные разделы доступны. У других ролей ссылки нет; прямой GET `/api/v1/system/status` запрещён. Без входа — 401.
2. Режим почты и параметры совпадают с действующим runtime env. При `EMAIL_ENABLED=false` отображается режим без почты и создание с начальным паролем. При `true` — работа с почтой. Изменения режима требуют штатного перезапуска сервисов.
3. Проверки показывают реальное состояние БД, IAM, MinIO, RabbitMQ и file_guard. Если один сервис недоступен или не готов, остальные результаты остаются видимыми; UI не показывает общий успех. Антивирус, который выключен или не готов, не получает зелёный статус.
4. При `FILE_GUARD_ENABLED=false` интеграция отмечена как отключённая, сетевого запроса нет. При отключённой почте отсутствие SMTP не становится аварией.
5. Видно время проверки, время ответа и срок работы процесса. Автообновление — каждые 30 секунд; скрытая вкладка не опрашивает API. При возвращении обновляется. Кнопка обновления не создаёт параллельные запросы.
6. При ошибке обновления ранее загруженные данные явно помечены как устаревшие. После восстановления связи отметка исчезает. При первом неуспешном запросе статус доступности не выдумывается.
7. Сведения о настройках не содержат паролей, токенов, ключей, строк подключения, email сервисной учётной записи и внутренних URL. Исключение с секретом не попадает в DTO.
8. Просмотр не создаёт пользователей, файлы, бакеты или сообщения и не отправляет письма. Изменение настроек и управление контейнерами из панели не предусмотрены.

## Выполненная проверка

- Backend: 22 теста — роли, список безопасных полей, ошибки без секретов, timeout, параллельные проверки, общий кэш, отключённый file_guard, готовность антивируса, безопасные проверки MinIO/AMQP и HTTP no-store.
- UI: 71 тест — режимы, статусы, устаревшие данные, опрос/отмена/видимость, навигация СА и запрет навигации другим ролям; также регрессия RoleRoute.
- Сборка backend/web и TypeScript, целевой ESLint, браузер desktop/mobile. При сбое API использован перехват 503 только в тестовом браузере; сервисы не останавливались.
- Реальные проверки локального стека прошли: БД, IAM, MinIO, RabbitMQ и file_guard доступны, антивирус готов, режим без почты. Анонимный запрос вернул 401. Сохранены desktop/mobile и снимок с имитацией сбоя API.
