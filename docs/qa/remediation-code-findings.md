## Архитектурные ограничения

- IAM: учётные данные, effective permissions и сессии. Backend: бизнес-статусы, org scope и actions. UI использует permissions/actions.
- Схема основной БД управляется внешним `order_database`; миграции должны быть согласованы с ним и отражены в `deploy/order_database/flyway/sql`, как требует `docs/operations/order-database-vps.md`.
- PostgreSQL остаётся внешним; публичный вход — gateway; новых identity providers и сервисов не требуется.
- План и анализ хранятся обычными документами в `docs/qa/`. Реализация выполняется самостоятельно, без Trellis и субагентов.
