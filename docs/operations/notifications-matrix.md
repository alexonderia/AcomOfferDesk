# Матрица уведомлений AcomOfferDesk

Сравнение каналов доставки: **на сайте** (центр уведомлений / колокольчик), **email**, **MAX**.

Актуально по коду backend + web на момент составления.  
Telegram (legacy) в таблицу не включён — по умолчанию отключён (`LEGACY_TELEGRAM_ENABLED=false`).

**Точные тексты** уведомлений и **превью писем** — в [разделе 8](#8-тексты-уведомлений-и-превью-писем).

---

## Условные обозначения

| Символ | Значение |
|--------|----------|
| ✅ | Отправляется в канал |
| ⚙️ | Зависит от настроек контрагента (см. ниже) |
| — | Не используется |
| 👤 | Только указанным ролям / получателям |
| 📧 | Внешний адрес (не обязательно пользователь системы) |

### Настройки контрагента (профиль → «Уведомления»)

В интерфейсе настраиваются три группы переключателей **Email / MAX**:

| Группа в профиле | Тип в backend | Что влияет |
|------------------|---------------|------------|
| **Сообщения** | `chat` | MAX при новом сообщении в чате КП |
| **Заявки** | `request` | Email о новой заявке; MAX о новой заявке и смене статуса заявки |
| **КП** | `offer` | MAX при принятии/отклонении КП |

Тип **`system`** в backend не выводится в матрицу профиля, но используется для:

- email при смене статуса контрагента (активен / неактивен / на проверке / ЧС);
- MAX «доступ открыт» / «доступ закрыт».

Системные записи в **центре уведомлений на сайте** (модерация, планы, служебные) на эти переключатели не завязаны.

Дополнительные условия:

- **Email** — нужен настроенный SMTP и email в профиле; для рассылки по заявкам — активный Keycloak-аккаунт.
- **MAX** — `MAX_BOT_ENABLED=true`, привязанный и подтверждённый MAX, статус пользователя `active`, канал MAX `approved`.
- **На сайте** — у контрагентов с Keycloak запись в центре уведомлений создаётся; без Keycloak — только staff-роли.

## 7. Сводка по каналам

### Только на сайте (колокольчик)

- КП: создание, обновление, смена статуса (в т.ч. удаление).
- Заявки: срок, ответственный, файлы, статус (для staff и контрагентов в центре).
- Сообщения в чате (дублируют push в реальном времени, если вкладка не открыта).
- Модерация и смена статусов пользователей (для админов / СБ).
- Планы экономии.
- Статус исходящей email-рассылки для сотрудника.

### Только email

- Подтверждение email.
- Новая заявка для зарегистрированных контрагентов.
- Приглашения (регистрация по заявке, портал, массовое приглашение).
- Смена статуса контрагента (при включённом `system`).

### Только MAX

- Сервисные сообщения бота (регистрация, ссылка, привязка).
- Push по заявкам, сообщениям и финальному статусу КП (при включённых настройках).

### Все три канала (для контрагента)

Прямого события «одновременно сайт + email + MAX» нет: при **новой заявке** контрагент получает запись в центре, письмо и MAX параллельно, но это три независимых механизма с разными условиями.

## 8. Тексты уведомлений и превью писем

Ниже — **точные формулировки** из кода (плейсхолдеры в фигурных скобках).  
Единый источник текстов для сайта, email и MAX: `shared/notification_copy.py`.  
Подпись кнопки-ссылки по умолчанию: **«Перейти в систему»** (`NOTIFICATION_BUTTON_LABEL`).  
Контекстные исключения: **«Перейти к регистрации»** (`REGISTRATION_BUTTON_LABEL`) — письмо незарегистрированному; **«Перейти к авторизации»** (`AUTHORIZATION_BUTTON_LABEL`) — доступ открыт.  
Для писем показано **превью макета**: белая карточка 600px на сером фоне `#f6f8fb`, заголовок **AcomOfferDesk**, синяя кнопка `#0969da`.

## 10. Ограничения и пробелы

1. **Email о сообщениях** — только отложенно (1 ч), если контрагент не прочитал; мгновенного email по чату нет.
2. **Нет email/MAX** при смене статуса КП (кроме обновления полей КП сотрудником), планах, модерации (кроме регистрации).
3. **Нет MAX** для создания КП, смены ответственного, планов, админских событий.
4. **Контрагент без Keycloak** не получает записи в центре уведомлений на сайте, но может получать email и MAX.
5. Отправка email и MAX не гарантируется при сбое SMTP / RabbitMQ / MAX API — на сайте у инициатора рассылки появится `email.failed`.
