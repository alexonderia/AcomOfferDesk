# Панель состояния системы

Суперадминистратор: меню **Состояние системы**, адрес `/admin/system`. На телефоне: **Прочее → Состояние системы**. Просмотр доступен только активному СА; остальные роли не получают доступ через прямой GET. Панель показывает текущие значения настроек, изменение конфигурации выполняется штатным развёртыванием.

## Что отображается

- Режим работы с почтой или без почты (`EMAIL_ENABLED`), способ создания сотрудников, окружение.
- Наличие настроек SMTP/IMAP, включение проверки файлов, secure/SameSite cookie, TTL ссылки на скачивание и билета чата.
- Время последнего успешного запроса из браузера, время проверки сервисов и uptime текущего процесса API (не всего Docker-стека).
- Результаты проверок API, бизнес-БД, IAM, MinIO, RabbitMQ и file_guard, с временем ответа отдельных зависимостей.

В разделе «Доступные режимы работы» перечислены оба режима с описанием возможностей:

- **Полный — с почтой:** разрешены почтовые уведомления, приглашения, подтверждение почты и восстановление пароля письмом; доступ сотрудников настраивается с использованием почты.
- **Ограниченный — без почты:** почтовые операции отключены; сотрудники создаются с логином и начальным паролем, восстановить забытый пароль может СА через сброс.

Активный режим выделен и отмечен «Активен», другой — «Не активен». При ошибке обновления отметка меняется на «Последний известный активный». В обоих режимах основные бизнес-функции доступны по правам роли, работают смена пароля в профиле и административный сброс. Сбой почтового сервиса автоматически не меняет выбранный режим.

`GET /api/v1/system/status` возвращает только явный перечень безопасных полей; response header — `Cache-Control: no-store`. Строки подключения, адреса внутренних сервисов, ключи, пароли, токены, email учётной записи и полная конфигурация не возвращаются. Ошибки удалённых сервисов подменяются общими сообщениями без текста исключения.

## Семантика проверок

| Сервис | Проверка | Предел результата |
| --- | --- | --- |
| API | Получен ответ панели | Это текущий процесс, не все экземпляры API |
| База данных | Подключение к бизнес-БД и `SELECT 1` | Не проверяет все таблицы и миграции |
| IAM | `/health/ready`, включая БД и конфигурацию подписи IAM | Не имитирует полный пользовательский вход |
| MinIO | Авторизованный `bucket_exists` для рабочего бакета | Не создаёт бакеты/объекты; не проверяет каждый файл |
| RabbitMQ | AMQP-подключение с рабочими учётными данными | Не публикует сообщения, не подтверждает работу consumers |
| file_guard | `/health` и `antivirus=ready` | Если антивирус отключён/не подтверждён, статус «Требует внимания»; если интеграция отключена в backend, запрос не выполняется |

Почта показана по настройкам. SMTP/IMAP-подключения, отправка и приём писем не выполняются; отсутствие SMTP при `EMAIL_ENABLED=false` не является сбоем. Готовность notifications_worker/maintenance, очередь, CPU/RAM и диск отдельно не измеряются. Панель не запрашивает Docker socket и не управляет контейнерами.

## Обновление и сбои

Зависимости проверяются параллельно с тайм-аутом до 3 секунд на каждую. Внутри процесса API результат кэшируется на 15 секунд с общей блокировкой для одновременных запросов. У каждого процесса свой кэш. Синхронная проверка MinIO выполняется в отдельном потоке с ограниченными сетевыми ожиданиями и без повторов.

Интерфейс запрашивает данные каждые 30 секунд на видимой вкладке, при возвращении на вкладку и по кнопке «Обновить». Повторный запрос может вернуть ещё действующий кэш; время проверки видно в панели. При уходе со страницы запрос отменяется, опрос останавливается. Запросы периодического обновления не накладываются друг на друга.

При сбое одной проверки остальные результаты сохраняются, общее состояние — «Есть замечания». Отключённая интеграция имеет отдельный нейтральный статус. При недоступности API сохраняется последний снимок с явной отметкой «Данные не обновлены». Без первого успешного ответа положительный статус не показывается. Вход и API требуют действующей авторизации и бизнес-БД: при полном отказе этих компонентов доступ к свежему снимку также может быть невозможен. Для такого случая нужен внешний мониторинг.

Панель не требует миграций БД. Проверка развёртывания и артефакты: `artifacts/qa/20261104-system-status/`.
