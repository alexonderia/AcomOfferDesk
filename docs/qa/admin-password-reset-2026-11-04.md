# Сброс паролей суперадминистратором — 2026-11-04

## Изменение

В карточках сотрудников и контрагентов доступна кнопка «Сбросить пароль». Только суперадминистратор может задать новый пароль другого пользователя без старого пароля. Все учётные записи суперадминистраторов защищены на backend и IAM. Диалог содержит новый пароль и повтор, переключатели видимости, отмену и объяснение завершения входа. Отмена и успешное сохранение очищают введённые значения.

Почта не нужна и не используется при любом `EMAIL_ENABLED`. Статус/роль/логин и непарольные required actions сохраняются. Нет миграции БД: используются существующие credentials, сессии, action tokens, authorization codes и аудит.

## Что проверить вручную

1. СА: открыть сотрудника → «Сбросить пароль», задать пароль 12–128 символов и повтор. Старый пароль не запрашивается. После успеха старый пароль не подходит, новый позволяет войти при активном статусе.
2. Повторить для контрагента; проверить вход по существующему логину. Блокировка, ожидание одобрения и отключение аккаунта не снимаются сбросом пароля.
3. Проверить ошибку несовпадения/длины, независимое отображение полей, отмену и повторное открытие с пустыми скрытыми полями. При сетевой ошибке форма остаётся открытой, сообщение позволяет повторить действие.
4. ВЭ, А, РП, Э, О, СБ и К: кнопки нет, прямой POST запрещён. Делегированные права управления пользователями не заменяют роль СА.
5. СА не может сбросить собственный пароль или пароль другого СА даже прямым POST; при рассогласовании роли бизнес-БД и IAM действует защита обоих сервисов.
6. Без активной IAM-связи сброс завершается ошибкой и не создаёт/активирует чужую учётную запись. При несовпадающем логине/роли IAM пароль не меняется.
7. До сброса открыть сессию пользователя и получить ссылки настройки/восстановления. После сброса refresh, старый браузерный вход IAM, ссылки и незавершённый код входа недействительны. Сессия инициатора сохраняется. Access JWT действует до TTL, штатно 300 секунд.
8. Проверить запись аудита с инициатором и целью; пароль не появляется в ответе/ошибках/аудите. В режиме с почтой письма также не отправляются.

## Автоматическая проверка

- Backend: проверка ролей, защищённых целей, привязки IAM, подтверждения/длины, вызова внутреннего API и HTTP-ответа 204.
- IAM: фактическое хеширование и вход новым/отказ старому паролю, отзыв refresh/browser/reset/setup/code, проверка сессии и актуальной роли инициатора, сохранение статуса, аудит без секретов, внутренний service token и безопасная ошибка 422.
- UI: доступность действия по ролям/цели, отправка без старого пароля, повтор, показ пароля, очистка при отмене и обработка ошибки.

Результаты запусков и сборки: `artifacts/qa/20261104-admin-password-reset/`. Проверки паролей выполняются на изолированных тестовых данных; пароли существующих пользователей локального приложения не меняются при проверке формы.
