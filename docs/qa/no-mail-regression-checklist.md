# Регрессия исправлений и режима без почты

Статус: выполнены локальная миграция, PostgreSQL-регресс, 47 основных автоматизированных сценариев и 4 E2E без почты — [расширенный протокол](expanded-regression-2026-11-02.md). Полный ручной повтор всех подпунктов исходного документа **не выполнен**. После очистки 03.11.2026 оставлен только основной `superadmin`; актуальный порядок подготовки и приёмки — [план проверки текущих изменений](current-changes-test-plan-2026-11-03.md). Исторические результаты не подменяют новый прогон на очищенных данных.

## Подготовка

- Записать URL, версии backend/IAM/web, Flyway history, время, роли и ID объектов.
- На копии PostgreSQL проверить новую миграцию, старые обращения с неизвестными автором/временем, пересчёт чатов, сохранение read/mute/archive.
- Подготовить корни А/Б, группы А1/А1.1/А2, пять ролей, запасного сотрудника, активного контрагента, открытую заявку не на Operator, КП и делегированный план экономиста.
- Запустить backend/worker с `EMAIL_ENABLED=false` и пустыми SMTP-настройками. Capability API и session должны возвращать одинаковый режим.
- Для каждого пункта записать «Пройдено / Ошибка / Заблокировано», роль, ID, шаг и HTTP-ответ без секретов. Пароли в протокол не переносить.

## Новые сценарии

| ID | Действие и ожидаемый результат |
| --- | --- |
| NM-01 | Уполномоченный сотрудник создаёт из UI пользователя без email, с логином/паролем; MAIN/IAM active, binding и членство согласованы; первый вход открывает разрешённую работу. |
| NM-02 | Создать контрагента с необязательными полями доступа и войти. Отдельно создать карточку без credentials для ручного КП. |
| NM-03 | Некорректный пароль, несовпадающий повтор, занятый логин, запрещённая роль и чужой юнит отклоняются; чужие credentials/статусы не меняются. |
| NM-04 | Повтор после потери ответа не создаёт дубль/сброс пароля/разблокировку. Другой пароль/роль отклоняются. Существующую компанию без credentials нельзя захватить через повторное создание. |
| NM-05 | В профиле сменить пароль по старому и повтору нового; писем нет, нужен новый вход, старый пароль отклоняется, новый принимается. Повторить для СА через меню. |
| NM-06 | Неверный старый пароль и неверный повтор нового не меняют аккаунт. Проверить CSRF, throttling, отсутствие секретов в ошибках/аудите. |
| NM-07 | Refresh и старая IAM browser session недействительны, pending setup/reset не меняют пароль. Другой access JWT учитывать до штатного `exp`. |
| NM-08 | Блокировка запрещает вход; восстановление сохраняет пароль. Потерянная привязка восстанавливается для проверенной identity; несовпадение логина/subject отклоняется. |
| NM-09 | Рассылка/приглашение/recovery недоступны с понятной причиной; нет новых SMTP-соединений, задач почтовой очереди и IMAP polling. Старая очередь сохранена. |
| NM-10 | Внутреннее уведомление и разрешённое сообщение чата доставляются без почты. Сетевая ошибка не скрывает разрешённую кнопку навсегда; повтор загрузки работает. |
| NM-11 | Включить почту с валидными настройками и пересоздать backend/worker: готовый аккаунт входит прежним паролем, настройки уведомлений доступны. Отдельно проверить письмо с нормативом. |
| NM-12 | При включённой почте создание с начальным паролем этим API отклоняется; штатные приглашения/саморегистрация и verified-email approval сохраняют правила. |

Повторить также остальные пункты, всего **47**. Исходные пустые результаты остаются успешными по указанию пользователя; новый прогон фиксируется отдельно, без изменения исходного протокола. Внешний интерфейс контрагента и почтовую доставку проверить с доступными внешними сервисами.
