Этот каталог **не входит** в `kustomization.yaml` (kustomize его не видит).

## `keycloak.yaml` + `make-configmaps.sh`

**Не разворачивать в контуре AcomOfferDesk.** Политика `policy_acom_no_keycloak_cod_jul2026`
(Graph RAG, источник — встреча у Тоток С.И. 23.07.2026):

- **verdict:** «Keycloak полностью запрещён»;
- **alternative:** «Мультифактор (корп. IAM)»;
- **impact:** «требуется смена auth-стека для ЦОД; текущий OIDC Keycloak на VPS — не канон для ЦОД»;
- **authority:** Тоток С.И. / СБ, 23.07.2026.

В коде это уже сделано: PR #53 «without_keycloak_and_others» (автор `alexonderia`, влит в
`dev` 04.09.2026, merge SHA `a804af5`) — `auth.py` −622 строки, добавлены `.env.iam.*`,
4 workflow поправлены. Ветка `test` (прод VPS) при этом не менялась.

## Как быть с входом (открытый вопрос, решает владелец)

1. **Целевой вариант (политика):** auth = корп. IAM (мультифактор). Манифест `keycloak.yaml`
   не возвращаем; переменные берём из `.env.iam.*` (ветка `dev`, PR #53).
2. **Переходный период** (KC ещё живёт в compose, приложение уже в k3s): `/iam` отдаёт
   **хостовый** nginx напрямую в compose-контейнер — k8s-контур Keycloak не касается.
   Локации `/iam/` в `config/gateway-nginx.conf` для этого **закомментированы**
   (статический `proxy_pass` на несуществующий Service не дал бы gateway подняться вовсе).

Файлы оставлены как история работ Ф5-3 (15.09.2026), чтобы не терять проработку —
но **включать их обратно в оверлей нельзя**.
