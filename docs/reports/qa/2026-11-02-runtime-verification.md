## PostgreSQL и аудит

[Исполняемый SQL-регресс](../../../backend/tests/sql/qa_v108_regression.sql) прошёл на мигрированной копии; тестовые записи откатываются транзакцией:

1. Настоящий trigger создания КП вызывает новую функцию. Руководители определяются по units; посторонний legacy `id_parent`, неактивный руководитель и экономист того же уровня не дают доступа. Перенос между корнями меняет участников, возврат сохраняет read/mute/archive.
2. Время feedback заполняется автоматически; удаление автора устанавливает `author_user_id=NULL`.
3. Provider `iam` принимается, вторая привязка пользователя к тому же провайдеру отклоняется.

Аудит приложения подтвердил у всех **39 исходных пользователей** по одной активной IAM-привязке, совпадение логина/роли и доступность содержимого **6 актуальных нормативов**. Исправление этих данных локально не требовалось.

У отдельного нового QA-пользователя воспроизведена неактивная привязка и выполнен `audit_qa_state --user ... --repair-bindings`. Связь восстановлена без изменения хеша пароля. Исходные аккаунты экспериментом не затрагивались. JSON-отчёты сохранены рядом с резервными копиями.

Внешние SMTP/IMAP-аккаунты не использовались. В финале capability API возвращает `email_enabled=false`, `notify.email` содержит 0 сообщений, worker сообщает об отключённой доставке.

Созданы отдельные QA-данные: префиксы `qa_v108_`, `QA v108`, заявки `QA-v108-...`. Они сохранены для повторных проверок. Секреты credentials находятся только в игнорируемом локальном файле.

Исправлены устаревшие ожидания E2E: актуальная IAM-форма использует `login`; экономист имеет `dashboard.process.read` и доступ к `/pm-dashboard` согласно существующему `permissions.py`. После этого протокола выполнено [расширенное продолжение](2026-11-02-expanded-regression.md) с дополнительными исправлениями backend; итоговая backend-регрессия — 761 passed. IAM 77, frontend unit 302, production build и итоговый ESLint успешны.

- Для другой БД сначала сверить её Flyway history; локальный смешанный набор автоматически не переносить.

Локальный QA-стек работает на `http://localhost:8080`, backend/worker без почты. Исходные private env не переписывались. Повторный запуск с имеющимися игнорируемыми QA-файлами:

```powershell

docker compose --env-file .env.dev -f docker-compose.yml -f docker-compose.dev.yml up -d --no-build iam backend web notifications_worker file_guard gateway
```

Для других окружений использовать штатную сборку и [инструкцию режима без почты](../../operations/no-mail-accounts.md). QA-файлы и резервные копии в Git не добавлять.
