# Смена пароля внутри профиля — 03.11.2026

По уточнению пользователя форма смены пароля размещена непосредственно в профиле. Отдельные кнопки в навигации и дополнительное окно убраны.

- `PasswordChangeForm` встроена в `ProfileButton`: текущий пароль, новый пароль, подтверждение и сохранение.
- Закрытие профиля сразу удаляет черновик парольных полей. Ошибки не закрывают профиль; успешная смена по-прежнему завершает сессию и требует нового входа.
- Профиль включён для СА в обычной, свёрнутой и мобильной навигации. Доступность формы зависит от серверного `manage_credentials`.
- В мобильной панели исправлено обрезание пункта «Прочее»: при переполнении он сохраняется, остальные разделы доступны внутри него. Поэтому профиль СА доступен и на узком экране.
- API смены пароля, проверка текущего пароля и права backend/IAM не изменялись.

## Дополнение: показ пароля в поле

По следующему уточнению пользователя добавлен общий `PasswordTextField`: локальное переключение `password/text` кнопкой «глаз», скрыто по умолчанию, независимо для каждого поля. Компонент используется в профиле, в `InitialAccountFields` и через `ValidatedTextField` в создании сотрудника. Сохранены ref/регистрация react-hook-form, значение, autocomplete, ограничения длины и дополнительные adornments. Переключатель имеет `type="button"`, доступное имя/состояние и недоступен вместе с disabled-полем. При закрытии профиля состояние видимости сбрасывается вместе с формой.

На IAM-страницах входа и задания пароля переключатель уже существовал; код IAM не менялся. Пройдено 13 целевых frontend-тестов, ESLint, TypeScript и production build. Web-контейнер обновлён. В браузере проверены вход, три поля профиля на компьютере, мобильный экран, клавиша Space, повторное скрытие, очистка после закрытия и поле создания сотрудника. Форма при переключении не отправляется; во время проверки пароли не менялись и пользователи не создавались. Артефакты: `artifacts/qa/20261103-password-visibility/`.
