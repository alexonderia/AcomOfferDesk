# NORM-001 — создание, замена, статус и защита от дублирования нормативного документа

## Preconditions

* Пользователь имеет права на создание и управление нормативными документами.
* Подготовлены два валидных файла: `Регламент-A.pdf` (содержимое A) и
  `Регламент-B.pdf` (содержимое B).

## Steps and expected results

1. Загрузить `Регламент-A.pdf` как новый норматив.
   - Создан один нормативный документ N1 со статусом `actual`.
2. Повторно загрузить файл с тем же именем, в том числе с другим содержимым.
   - Показано понятное сообщение, что норматив с таким именем уже существует;
     success-notification отсутствует и в списке остаётся одна строка.
3. Заменить файл N1 на `Регламент-B.pdf` через действие «Заменить».
   - Идентификатор N1 не меняется, имя/содержимое текущего файла обновляются,
     а статус сохраняется.
4. Изменить статус N1 на `outdated`, затем обратно на `actual`.
   - Меняется только статус; файл не заменяется.
5. Создать Request с N1 в статусе `actual`, затем заменить N1 на другой файл.
   - Уже созданная Request скачивает прежний snapshot; новая Request получает
     текущий файл N1.
6. Попробовать создать Request с N1 в статусе `outdated` и с неизвестным ID.
   - Обе операции отклоняются.
7. Повторить шаг 2 прямым `POST /api/v1/normative-files`.
   - Ответ `409`; новая запись `NormativeFile` и новый `File` не появляются.

## Scope notes

* Duplicate в нормативном домене определяется только по исходному имени.
  Одинаковый файл в Request, Offer или Message не участвует в этой проверке.
* DELETE не является частью NORM-001.
