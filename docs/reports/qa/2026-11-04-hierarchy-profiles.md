# Профили сотрудников из иерархии — 04.11.2026

Имя сотрудника открывает профиль поверх текущей иерархии: в обзоре, составе узла, схеме, списке и списке нераспределённых сотрудников. Закрытие профиля возвращает к тому же представлению; схема не размонтируется и сохраняет масштаб и прокрутку. Нажатие доступно мышью, Enter и пробелом. Перенос и открепление остаются отдельными действиями.

Профиль показывает ФИО, логин, роль, статус, телефон и почту. Данные запрашиваются при открытии; закрытие отменяет незавершённый запрос. Ошибка показывается с возможностью повторить загрузку.

`GET /api/v1/users/{user_id}/details` требует `users.read` и проверяет область через `UnitHierarchyService.can_view_user`, как чтение иерархии пользователя. Это просмотр контактов без полномочий на изменение сотрудника. СА доступны нераспределённые сотрудники; остальные роли ограничены своей действующей областью. Список контактов не загружается заранее. Контрагенты открываются через свой раздел. Ответ содержит только шесть полей профиля и `Cache-Control: no-store`.

Проверки:

- 63 серверных проверки: новый контракт, существующие ограничения администрирования пользователей и юнитов. Включены видимый РП, собственный профиль, профиль подчинённого, нераспределённый сотрудник для СА, запрет чужого корня/ветки, запрет без `users.read`, отсутствие пользователя и отдельная граница контрагентов.
- 30 проверок интерфейса иерархии: открытие из дерева и списка, контакты, независимость управляющих кнопок, ошибка/повтор, отмена запроса и отсутствие запоздалых данных.
- Сборка TypeScript/Vite и ESLint изменённых компонентов. В `PeopleTree.tsx` остаётся существующее предупреждение Fast Refresh о смешанных экспортах.

Ручной проход: открыть профиль из обзора, затем изменить масштаб схемы и открыть профиль вложенного сотрудника; закрыть и проверить прежний масштаб. Повторить в режиме «Список», через Enter/пробел и на узком экране. Для проверки ограничений войти сотрудником и запросить профиль другого подразделения: контакты не должны возвращаться.
