# Созданный сотрудник не виден в списке — 04.11.2026

## Причина

В локальной бизнес-БД и IAM существует активный аккаунт `lead_economist` с фактической ролью **«Экономист»** (`economist`, бизнес role_id=6). Членства в подразделениях нет. Администратор-создатель `administrator` также не назначен в подразделения. По действующим правилам администратор видит сотрудников своих подразделений, а СА — всех сотрудников выбранной роли. Логин не определяет роль.

Интерфейс позволял администратору открыть создание из вкладки «Ведущие экономисты», хотя по правилам он создаёт только экономистов/операторов. В форме предлагалась другая разрешённая роль, уведомление не уточняло её, а список после создания оставался прежним. У СА сотрудник должен находиться в «Экономисты», а не в «Ведущие экономисты».

## Изменения

- Для администратора действие создания соответствует роли открытой вкладки. Во вкладках недоступных ему ролей кнопка создания не показывается. Для СА выбор допустимой роли сохраняется.
- Поле роли управляется значением формы; отображаемая роль синхронизирована с отправляемой.
- Ответ регистрации содержит `visible_to_creator`: backend определяет видимость по актуальной иерархии после назначения. Правила доступа не расширены.
- После сохранения форма закрывается, в уведомлении и сообщении над списком указаны логин и фактическая роль. При смене роли открывается её список.
- Если новый сотрудник вне области создателя, показано предупреждение с направлением к СА для назначения.
- В форме администратора заранее объяснены допустимые роли и зависимость видимости от назначения.

Существующие пользователи, пароли, роли и назначения при исправлении не меняются. Миграция не требуется. Чтобы получить ведущего экономиста, СА должен назначить соответствующую роль; для видимости у администратора требуется назначение в доступное ему подразделение.

## Проверка

- Backend: 43 интеграционных проверки, в том числе создание нераспределённым администратором в обоих почтовых режимах, явный `visible_to_creator=false`, отсутствие сотрудника в списке администратора и наличие в списке СА, запрет создания ВЭ администратором.
- UI: 16 проверок модели формы и выбора ролей, перехода к фактической роли, закрытия формы и предупреждения о видимости.
- TypeScript и целевой ESLint прошли. Логи сборки и браузера: `artifacts/qa/20261104-created-user-visibility/`.
- Реальный браузер СА: `GET /api/v1/users?role_id=6` и список «Экономисты» содержат существующий аккаунт `lead_economist` с ролью 6.
- В браузерных фикстурах администратора проверены отсутствие создания из вкладки ВЭ, совпадение отображаемой и отправляемой роли оператора, пояснение перед созданием, закрытие формы и постоянное предупреждение после создания вне видимости. POST регистрации перехвачен в браузере; реальных пользователей проверка не создаёт.
- Backend/web пересобраны, запущены, gateway обновлён. Миграция не выполнялась.
